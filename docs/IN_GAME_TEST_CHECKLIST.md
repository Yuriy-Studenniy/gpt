# Единый игровой чек-лист — AI Stalker Companion

Цель: один консолидированный прогон главы 1 на **S.T.A.L.K.E.R.: Call of Pripyat 1.6.02, оригинальный X-Ray**.

**Статус:** не запускался. Этот документ описывает план проверки, а не подтверждает работу функций в игре.

## Перед началом

- [ ] Сделана копия текущего сохранения и отдельная тестовая копия.
- [ ] Зафиксированы точная версия игры, список модификаций и используемое сохранение.
- [ ] В тесте нет других изменений скриптов помимо текущей ветки проекта.
- [ ] Доступен лог игры; после прогона сохранён лог с момента загрузки тестового сохранения.

## 1. Создание и идентичность NPC

- [ ] При первой загрузке создаётся ровно один компаньон.
- [ ] Компаньон появляется на доступной позиции, не внутри игрока, стены или опасной геометрии.
- [ ] NPC зарегистрирован с уникальным Story ID gpt_companion_main, squad — gpt_companion_squad.
- [ ] Повторные обновления игрока и повторная загрузка не создают второго NPC или второго squad.
- [ ] Если безопасной точки спавна нет, NPC не появляется поверх игрока; повторная попытка не создаёт дубликат.
- [ ] Если NPC умер, автоматическая настройка не воскрешает его и не создаёт замену.
- [ ] Стартовый инвентарь соответствует профилю: АКС-74У, ПМ, патроны, нож, stalker_outfit, фонарь, 2 аптечки, хлеб, консервы и 1 энергетик; бинтов нет; повторная загрузка не добавляет дубликаты.

## 2. Следование, бой и лечение

- [ ] Компаньон следует штатной схеме CoP и не застревает при изменении дистанции или позиции игрока.
- [ ] В бою он использует доступное оружие и штатную боевую логику.
- [ ] При отсутствии подходящих патронов не возникает бесконечного переключения оружия или ложного подтверждения выстрела.
- [ ] При ранении включается штатная wounded-логика и используется аптечка, если она доступна.
- [ ] Еда, питьё и обыск трупов не прерывают бой, опасность или wounded-состояние.

## 3. A-Life, online/offline и переходы уровней

- [ ] При удалении игрока на расстояние спутник корректно переходит в offline A-Life.
- [ ] Во время offline-симуляции squad ориентирован на игрока, а не выбирает случайную Smart Terrain.
- [ ] При возвращении в зону активности NPC появляется снова без дубликата.
- [ ] Выполнена последовательность переходов Затон → Юпитер → Припять → обратно.
- [ ] На каждом переходе сохраняются тот же Story ID и ожидаемое членство в squad.
- [ ] После переходов не теряется NPC, не остаётся пустого дублирующего отряда, не возникает повторный спавн.

## 4. Потребности, еда и сохранение

- [ ] На новом сохранении hunger/thirst получают начальную временную отметку без скачка.
- [ ] При продвижении игрового времени hunger/thirst растут; пауза или изменение реального времени сами по себе не ускоряют их.
- [ ] При достижении порога компаньон использует хлеб, колбасу или консервы для голода; стартовый энергетик — для жажды.
- [ ] Thirst проверяется через стартовый energy_drink; после его употребления проверить, может ли спутник подобрать следующий энергетик с трупа.
- [ ] Предмет расходуется только после фактического eat; потребность снижается только после подтверждённого потребления.
- [ ] Если компаньон в бою, под угрозой или ранен, он не пытается есть или пить.
- [ ] Потребности сохраняются после save → load.
- [ ] Потребности продолжают расти при offline-симуляции.
- [ ] После еды не происходит повторного начисления уже учтённого времени.

## 5. Обыск трупов, передача предметов и резервации

- [ ] Компаньон начинает поиск только при отсутствии врага, опасности и ранения.
- [ ] Из трупа забираются только разрешённые и нужные предметы.
- [ ] Проверить, что companion-only denylist блокирует все текущие специальные секции: Nimble, Zulu, Trapper, Barge, Joker, Snag и actor-unique варианты.
- [ ] Убедиться, что обычные NPC по-прежнему используют vanilla loot whitelist: denylist действует только на спутника.
- [ ] Проверить, что спутник не подбирает бинты, поскольку текущая wounded-схема их не использует.
- [ ] После transfer_item предмет действительно принадлежит инвентарю компаньона; лимиты добычи меняются только после подтверждения владельца.
- [ ] За один обыск не подбирается несколько предметов одной группы экипировки.
- [ ] Подбираются только патроны, совместимые с ammo_class оружия; запас не пополняется бесконечно.
- [ ] Два NPC не обыскивают одновременно один и тот же труп.
- [ ] Если владелец резервации умирает, уходит offline или переключается с corpse-search action, другой NPC может выбрать этот труп.
- [ ] При появлении врага или опасности во время пути резервация освобождается.
- [ ] Если тело активно выбрано NPC, release_body_manager не удаляет его по таймеру или дистанции.
- [ ] Если все доступные тела зарезервированы, лимит тел может временно превышаться, но активная цель не удаляется.
- [ ] После успешного обыска или ошибки не остаётся застрявшей резервации и временного loot-контекста.

## 6. Снаряжение

- [ ] Оружие сравнивается отдельно внутри сопоставимых типов.
- [ ] Оружие с явно худшим состоянием не вытесняет лучший аналог из-за ошибочного значения.
- [ ] Костюм и шлем не заменяются на очевидно худший вариант по доступным защитным полям и состоянию.
- [ ] Детектор более высокого поддерживаемого ранга имеет приоритет.
- [ ] Не подбираются защищённые уникальные секции из denylist; список расширяется при добавлении новых уникальных предметов.

**Оговорка по оценке:** текущие баллы оружия, брони и шлемов — эвристика, а не точная боевая симуляция. Пулестойкость через bone protection и AP патрона не вычисляется для произвольного предмета-кандидата текущим Lua API. В этом прогоне проверяем отсутствие очевидно плохого выбора; точность рейтинга не считаем подтверждённой.

## 7. Смерть и очистка squad

- [ ] При смерти единственного участника новый компаньон автоматически не создаётся.
- [ ] Пустой companion squad не запускает обычный generic A-Life target cycle.
- [ ] Story ID умершего NPC не продолжает указывать на другой объект.
- [ ] После сохранения и загрузки умерший компаньон не воскрешается и не дублируется.
- [ ] Обычные squad и NPC продолжают работать без ошибок.

## 8. Регрессия обычных NPC

Проверить рядом с компаньоном несколько обычных сталкеров разных группировок.

- [ ] Обычные NPC подбирают предметы по ванильным правилам, без companion scoring.
- [ ] Их потребности, еда и поведение не меняются.
- [ ] Их A-Life squad выбирают цели по обычной логике, а не игрока как обязательную цель.
- [ ] Их резервации трупов освобождаются при прерывании поиска.
- [ ] Нет Lua-ошибок при обычном обыске, передаче предметов и смерти.
