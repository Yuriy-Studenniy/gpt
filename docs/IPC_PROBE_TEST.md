# M1 — проверка файлового IPC с оригинальным CoP 1.6.02

Статус: двусторонний файловый обмен подтверждён в retail CoP. Диагностический probe сохранён как вспомогательный тест; дальнейшее развитие идёт в Companion Runtime.
Ветка: world-model-completion.

## Контракт

Запрос: v1 <request_id> ping

Ответ: v1 <request_id> ok pong_gpt_companion_ipc_probe_v1

Lua hook находится в уже загруженном bind_stalker.script и опрашивает только четыре фиксированных файла в $app_data_root$. Это временный smoke-test: он не вызывает LLM, HTTP, сокеты и игровые действия.

## Подтверждение в игре

В retail CoP 1.6.02 PowerShell записал запрос с ID 8a1d5d73e47048b9. Lua:
- прочитала и удалила командный файл;
- выставила state=reply_written и detail=8a1d5d73e47048b9;
- создала reply-файл с точным тем же request ID и pong payload.

Это подтверждает фактическое чтение команды и обратную запись ответа движком. Python отдельно ранее успешно опубликовал команду, которую Lua прочитала. Полный Python poll-wrapper не получил подтверждённый success в консоли, потому что игровые окна сворачивались/приостанавливались при переключении и PowerShell Job имел ограничения кодировки/вывода. Это не основание снова повторять ручной ping: файловый контракт в целевой игре уже доказан.

## Python probe

Инструмент находится в tools/gpt_companion_ipc_probe.py.

Важные свойства актуальной версии:
- безопасно выводит ошибки в Windows PowerShell Job;
- проверяет request ID, чтобы не принять старый ответ;
- не удаляет существующий незавершённый запрос;
- не удаляет status/reply перед отправкой;
- при тайм-ауте сохраняет свою команду и диагностические файлы, потому что игра может быть приостановлена в свёрнутом окне.

Автоматизированный тест эмулирует Lua-ответ с тем же ID и отдельно проверяет, что timeout не уничтожает запрос.

## Границы

M1 закрывает техническую возможность обмена файлами с оригинальным X-Ray. Он не подтверждает производственную надёжность очереди, retry/recovery при аварийном завершении или работу при свёрнутой игре. Эти свойства реализуются и проверяются как часть Runtime/bridge, без отдельного повторения smoke-test.
