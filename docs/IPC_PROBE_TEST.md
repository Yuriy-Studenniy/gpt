# M1 — проверка файлового IPC с оригинальным CoP 1.6.02

Статус: файловый транспорт вручную подтверждён в retail CoP 1.6.02. Автоматический Python round-trip пока не подтверждён; для него исправлен диагностический probe.
Ветка: world-model-completion.

## Контракт

Запрос: `v1 <request_id> ping`

Ответ: `v1 <request_id> ok pong_gpt_companion_ipc_probe_v1`

Lua hook находится в уже загруженном `bind_stalker.script` и опрашивает только четыре фиксированных файла в `$app_data_root$`. Это временный smoke-test: он не вызывает LLM, HTTP, сокеты и игровые действия.

## Что уже подтверждено

В retail CoP PowerShell записал запрос с ID `8a1d5d73e47048b9`. Lua прочитала и удалила командный файл, записала `state=reply_written` и создала ответ с тем же ID.

Это доказывает, что X-Ray может читать файл команды и создавать файл ответа. Отдельный Python probe также создавал командный файл, который Lua ранее читала, но Python-клиент не получил подтверждённый ответ в своём процессе.

## Исправления автоматического probe

Предыдущая версия Python публиковала команду через временный файл и `os.replace()`. Теперь probe создаёт итоговый `gpt_companion_ipc_cmd.txt` напрямую, записывает строку, сбрасывает буфер и закрывает файл. Это намеренно повторяет прямую запись, уже сработавшую при ручной проверке, и исключает атомарное переименование как возможный источник несовместимости. Одновременно используется эксклюзивное создание, чтобы не затирать незавершённую команду.

Lua продолжает опрашивать файл, пока игра активна. Временное исключение при `io.open` больше не выключает обработчик: ошибка фиксируется и попытки продолжаются. Статус `poll_active` обновляется не реже одного раза в пять секунд и содержит значение игрового таймера; это позволяет отличить остановку actor update от ошибки открытия файла. После успешного чтения командный файл удаляется только после успешного чтения содержимого, чтобы ошибка чтения не теряла запрос. Обработчик принимает следующие команды без обязательного перезапуска игры.

При тайм-ауте Python сохраняет команду и выводит её точный путь, размер, время изменения и содержимое. Старый ответ с другим `request_id` не считается успехом.

## Проверки

`tests/test_ipc_probe.py` проверяет ответ с тем же ID, сохранение команды после тайм-аута и запрет перезаписи незавершённой команды. Эти тесты эмулируют игру; сами по себе они не заменяют проверку в CoP.

## Границы

Текущие изменения — диагностическая коррекция и проверка совместимости файловой публикации. Они ещё не доказывают успешный Python → Lua → Python round-trip в игре. После установки обновлённых двух файлов нужен один контрольный прогон; повторять прежний ручной ping не требуется.
